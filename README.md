# مراس العلم

منصة تعليم جامعي عربية تعمل بواجهة ويب وتطبيق Expo/React Native، وتشترك جميع القنوات في حسابات المستخدمين والكتالوج والصلاحيات والطلبات والدعم والإشعارات والتقدم الدراسي.

ملخص التطوير الشامل لهذه الحزمة موجود في [`UPGRADE_20260828.md`](./UPGRADE_20260828.md).

## البنية

| المجلد | المحتوى |
|---|---|
| `backend/` | تطبيق Next.js، واجهات API، المصادقة، PostgreSQL عبر Drizzle، الدفع، المساعد، الفيديو، ولوحات الطالب والمشرف والإدارة. |
| `mobile/` | تطبيق Expo/React Native لنظامي Android وiOS ونسخة الويب، مرتبط بواجهات `/api/mobile/*`. |

## الجاهزية الحالية

- الهوية الرسمية موحدة بدقة عالية: علامة **M والنجمة كاملة** في أيقونات Android وiOS وPWA وSplash والإشعارات، والشعار الرسمي الكامل في مواضع العلامة داخل الويب والتطبيق.
- تجربة عربية RTL محسنة من البداية إلى النهاية، مع إطلاق احترافي وOnboarding من خمس محطات، وبحث سريع وفلاتر إضافية منظمة داخل لوحة مستقلة بدل ازدحام الصفحة.
- مفاتيح تشغيل إدارية للتسجيل والشراء وطلبات المواد والدعم وجولة البداية ورسالة الصيانة؛ تطبق على الويب وExpo وتتحقق منها واجهات الخادم الحساسة كذلك.
- لوحتا إدارة متكافئتان في الويب وExpo لإدارة الكتالوج والمحتوى والحسابات والتجارة والدعم والإعلانات والإشعارات؛ تستخدمان الخيارات المرتبطة المسموح بها وعقود API نفسها، مع تأكيد صريح قبل تحديث حساب موظف موجود.
- تحديث تلقائي دون إعادة تحميل يدوية: الويب يستخدم Server-Sent Events مع إشعارات PostgreSQL، والتطبيق يجلب التغييرات في المقدمة ويحدّث React Query حسب قناة التغيير.
- عزل بيانات الجلسة والإعلانات والفلاتر وذاكرة الاستعلامات عند تبديل الحساب، مع حفظ ذري للرمز وإلغاء تسجيل Push الخاص بالجلسة السابقة.
- مساعد عربي يفتح صفحات التطبيق الأصلية بأمان، ويحفظ عبارة البحث عند الانتقال إلى الكتالوج، ويدعم السلة والمفضلة والفواتير وصفحات السياسات والمعلومات العربية.
- 85 جهة تعليمية و168 تخصصًا فريدًا و3,009 روابط جهة–تخصص تُزرع تلقائيًا في PostgreSQL عند أول تشغيل.
- المواد الثماني الظاهرة في الرئيسية تصبح سجلات إدارية حقيقية، لكل مادة أربع وحدات وهيكل دروس كامل (256 موضع درس إجمالًا) جاهز لإضافة الفيديوهات.
- المادة غير المكتملة تظهر للطالب بصفتها «قريبًا»، ولا يسمح الخادم بإضافتها للسلة أو دفع قيمتها حتى تكتمل كل فيديوهاتها ويوجد درس تجريبي جاهز.
- رفع مرفقات الطلبات والدعم والفيديوهات يتم بالبث إلى التخزين بدل تحميل الملف كاملًا في ذاكرة الخادم، مع فحص النوع والتوقيع والحجم والعدد والتنظيف عند الفشل.
- الهوية البصرية موحدة في الهيدر والفوتر وصفحات الدخول والتسجيل والتطبيق والأيقونة، وتدعم المظهر الفاتح والليلي والثيمات وأحجام النص المختلفة.

## تشغيل الخادم محليًا

يتطلب Node.js 22 أو أحدث وPostgreSQL 14 أو أحدث.

```bash
cd backend
npm ci
cp .env.example .env
# عدّل DATABASE_URL وبقية المتغيرات السرية
npm run db:migrate
npm run dev
```

يفتح الخادم عادة على `http://localhost:3000`. عند غياب قاعدة البيانات يكتمل `npm run build` لكن يبقى الكتالوج العام فارغًا ولا تُدمج بيانات ثابتة مع بيانات الإنتاج، وتعيد واجهة `/api/health` حالة واضحة حتى تضبط `DATABASE_URL`. يمكن تفعيل بيانات العرض محليًا فقط عبر وضع demo الصريح، وهو مرفوض في الإنتاج.

## تشغيل التطبيق

```bash
cd mobile
npm ci
cp .env.example .env
npm start
```

اضبط `EXPO_PUBLIC_API_URL` على عنوان Railway النهائي، مثل `https://your-service.up.railway.app`. لا تضع أي مفتاح Tap أو مفتاح مزود المساعد أو سر جلسات داخل التطبيق.

## النشر على Railway

النشر المقصود هو مجلد `backend`؛ يحتوي على `Dockerfile` و`start-railway.sh`. أنشئ خدمة Railway من هذا المجلد، أضف خدمة PostgreSQL أو اربط قاعدة PostgreSQL الموجودة، ثم أضف متغيرات `.env.example` إلى Variables. يجب أن تكون `DATABASE_URL` هي قيمة اتصال PostgreSQL التي يوفرها Railway.

أضف Volume دائمًا واربطه بالمسار `/data` حتى تبقى الفيديوهات والمرفقات والشعارات محفوظة. يبدأ الخادم عبر `start-railway.sh`، يطبق `drizzle-kit migrate` تلقائيًا، ثم يشغل Next.js على `0.0.0.0:$PORT`. استخدم `/api/health` كمسار فحص الصحة.

بعد الهجرات يشغّل السكربت تهيئة الكتالوج تلقائيًا (`AUTO_SEED_CATALOG=true`). الوضع الموصى به هو `CATALOG_SEED_MODE=core` لأنه يضيف دليل الجهات والتخصصات والمواد الأساسية فقط ويحافظ على تعديلات الإدارة. استخدم `full` فقط إذا أردت توليد قوالب مواد كثيرة لكل روابط التخصصات وتقبل زمن وحجم التهيئة الأكبر.

## التزامن الفوري والأداء

تُحدّث triggers الهجرة رقم `0010` عدّادات قنوات `catalog` و`settings` و`announcements` و`student` و`supervisor` و`admin` و`support`، ثم ترسل `pg_notify`. يستمع كل خادم إلى الإشعار ويبث فقط القنوات المسموح بها للجلسة عبر `/api/sync/stream`. يوجد polling احتياطي متباعد للاتساق عند انقطاع SSE، ويبطؤ تلقائيًا عندما تكون الصفحة مخفية. لذلك تظهر إضافات الإدارة وتغييرات الطلبات والدعم والإشعارات دون تحديث الصفحة يدويًا، بما في ذلك عند تشغيل أكثر من نسخة خادم متصلة بقاعدة PostgreSQL نفسها.

## الخدمات الاختيارية

يعمل المساعد بمحرك معرفة عربي محلي يقرأ الكتالوج والإعدادات الحية، ويمكن توسيعه للإجابة عن الأسئلة العامة عبر `OPENAI_API_KEY` و`OPENAI_API_URL` و`ASSISTANT_MODEL` من الخادم فقط. عند غياب المفتاح الخارجي يبقى المحرك المحلي فعالًا. الدفع يحتاج مفاتيح Tap الحقيقية، وإرسال استعادة كلمة المرور يحتاج Resend. جميع الأسرار تبقى في الخادم.

## مصدرية الكتالوج وتحديثه

يحتوي [`CATALOG_SOURCES.md`](./CATALOG_SOURCES.md) على مصادر مجلس شؤون الجامعات وادرس في السعودية، وتاريخ آخر تحقق، والجهات التي صُححت أسماؤها دون إنشاء تكرارات. يحمل كل برنامج حالة واضحة: `official-program` للبرنامج المستخرج من مصدر رسمي، و`discovery` لخريطة المجال العامة، و`pending-review` لما أدخله المشرف ولم يعتمد بعد.

تهيئة `core` تحوّل المواد الثماني الأساسية إلى سجلات قاعدة بيانات مرتبطة بجهاتها وتخصصاتها، وتضيف وحداتها ووصفها وقوالب دروسها مع حالة «بانتظار الفيديو». لا تُعد هذه القوالب فيديوهات جاهزة ولا تسمح بالشراء. تصبح المادة قابلة للدفع تلقائيًا فقط بعد أن يكون لكل درس منشور فيديو جاهز وأن يتوفر درس تجريبي. تعديلات الإدارة على المواد أو الوحدات أو الدروس الموجودة لا تُستبدل عند إعادة التشغيل.

## التحقق قبل النشر

```bash
cd backend
npm run lint
npm run build
npm test

cd ../mobile
npm run typecheck
npm run lint
npm run test:contracts
EXPO_PUBLIC_API_URL=https://your-service.up.railway.app npx expo export --platform all --output-dir dist
```

لا ترفع ملفات `.env` أو مجلدات `node_modules` و`.next` و`dist` إلى المستودع. بعد أول نشر أنشئ حساب الإدارة باستخدام واجهة `POST /api/admin/staff` الموثقة داخل `backend/README.md`، ثم نفّذ اختبار قبول في Railway للتسجيل والدخول ورفع غلاف وشعار وفيديو ومرفق طلب ومرفق دعم والدفع عبر Tap Sandbox.


## الأمن قبل الإطلاق

اقرأ [`SECURITY.md`](./SECURITY.md) وطبّق متغيرات الأسرار المنفصلة، ومنها `TAP_WEBHOOK_SECRET` إن كان متاحًا من Tap، و`ADMIN_API_TOKEN` و`ADMIN_UPLOAD_TOKEN` المختلفان. لا تضع الأسرار في تطبيق Expo أو مستودع Git. نسخ الإنتاج من التطبيق ترفض عنوان API غير HTTPS؛ أثناء التصدير استخدم `EXPO_PUBLIC_API_URL=https://your-service.up.railway.app`.

نجاح البناء وفحص الاعتماديات لا يثبت انعدام الثغرات. شغّل اختبار PostgreSQL وTap Sandbox ورفع الملفات واختبار حمل واختبار اختراق مستقل قبل فتح التسجيل العام، وأنشئ نسخًا احتياطية مشفرة واختبر استعادتها.
