# قوالب مراس العلم — Resend

القوالب الثلاثة مرتبطة الآن بإرسال المنصة من الخادم، بهوية الموقع العربية وشعاره وألوانه، وعلى النطاق `https://marasalelm.com`. يُنشئ الخادم الرمز أو رابط الاستعادة ويضيف حسابات التواصل المحفوظة في الإدارة إلى كل رسالة جديدة. لا تحتاج إلى كتابة طلب API يدوي، ولا إلى وضع مفتاح Resend داخل المتصفح أو التطبيق.

## الملفات الجاهزة

| ملف HTML | الاستخدام | اسم / alias مقترح | متغير الربط الاختياري في Railway |
| --- | --- | --- | --- |
| [01-verify-email.html](01-verify-email.html) | تأكيد البريد الإلكتروني | `meras-verify-email` | `RESEND_TEMPLATE_VERIFY_EMAIL` |
| [02-change-password.html](02-change-password.html) | تأكيد تغيير كلمة المرور من الحساب | `meras-change-password` | `RESEND_TEMPLATE_CHANGE_PASSWORD` |
| [03-reset-password.html](03-reset-password.html) | استعادة كلمة المرور عند نسيانها | `meras-reset-password` | `RESEND_TEMPLATE_RESET_PASSWORD` |

الرمز في القالبين الأول والثاني صالح 10 دقائق ولمرة واحدة. رابط الاستعادة في الثالث صالح 15 دقيقة ولمرة واحدة. تأكيد البريد يُجرى للحساب، وليس قبل كل عملية شراء.

## التشغيل الافتراضي: لا يلزم إنشاء قوالب داخل Resend

بعد نشر الكود، يحتاج الإرسال إلى `RESEND_API_KEY` صالح و`EMAIL_FROM` من نطاق موثّق في حساب Resend، مع إعداد نطاق المنصة:

```env
APP_URL=https://marasalelm.com
NEXT_PUBLIC_SITE_URL=https://marasalelm.com
```

أبقِ متغيرات `RESEND_TEMPLATE_*` الثلاثة فارغة إذا أردت استخدام التصميم الموجود في ملفات المشروع مباشرة. في هذه الحالة يقرأ الخادم ملف القالب، ويملأه بالقيم الصحيحة، ثم يرسل **HTML مع نسخة نصية بديلة** عبر Resend. رفع HTML إلى لوحة Resend ليس شرطًا لتشغيل هذا المسار.

لا توجد مفاتيح أو أرقام رموز ثابتة جاهزة للنسخ: استخدم مفتاح حسابك ومرسلًا موثّقًا فعلًا. امتلاك الموقع شهادة HTTPS لا يعني أن إرسال البريد من نطاقه موثّق؛ راجع [إعداد نطاقات الإرسال لدى Resend](https://resend.com/docs/dashboard/domains/introduction).

## استخدام القوالب داخل لوحة Resend — اختياري

اختر هذا المسار إذا أردت إدارة تصميم البريد ونشر إصداراته من حساب Resend:

1. أنشئ قالبًا لكل ملف من الملفات الثلاثة، واستورد محتوى HTML كاملًا. راجع [طريقة إنشاء قالب واستيراد HTML](https://resend.com/docs/dashboard/templates/create-template).
2. عرّف المتغيرات الـ13 الموضحة أدناه في كل قالب، وجميعها من نوع **String**، لا Number. استخدم الأسماء كما هي، بما فيها الأحرف الكبيرة والشرطة السفلية.
3. لا تضف قيمًا افتراضية للرمز أو رابط الاستعادة. يُفضل ترك جميع المتغيرات دون قيم افتراضية؛ المنصة ترسلها كلها في كل رسالة، وتُرسل سلسلة فارغة في خانات التواصل غير المستخدمة.
4. راجع المعاينة، ثم انشر القالب باستخدام **Publish**. لا تعتمد على قالب ما زال مسودة. أي تعديل لاحق داخل Resend يحتاج نشر النسخة الجديدة.
5. انسخ **ID الحقيقي للقالب المنشور** إلى المتغير المقابل في Railway، ثم أعد نشر / تشغيل الخدمة. يمكن استخدام alias إذا ضبطته صراحة داخل Resend؛ اسم العرض وحده ليس ضمانًا أنه alias صالح. راجع [إرسال القوالب المنشورة](https://resend.com/docs/dashboard/templates/introduction).

عند ضبط ID يرسل الخادم `template.id` ومتغيراته فقط، دون جمعها مع `html` أو `text` في الطلب نفسه. تبقى بيانات المرسل والمستلم وموضوع الرسالة تحت تحكم كود المنصة؛ لهذا قد يتقدم موضوع الخادم على الموضوع الافتراضي الذي كتبته داخل Resend. هذا مطابق [لقواعد إرسال القوالب لدى Resend](https://resend.com/docs/dashboard/templates/template-variables).

إذا تجاوز محتوى أحد متغيرات التواصل الحد الذي يتعامل معه الربط، يستخدم الخادم ملف HTML المحلي مع النسخة النصية بدل إرسال متغير أكبر من الحد. لا يوجد رجوع إلى رمز أمان ثابت أو رابط تجريبي، ولا يعيد الخادم الإرسال تلقائيًا بوسيلة أخرى عند خطأ من المزود. ID غير صحيح أو قالب غير منشور قد يمنع الإرسال؛ احذف قيمة ID لاستخدام الوضع الافتراضي إلى أن تصلح إعداد القالب.

## متغيرات كل قالب: 13 متغيرًا

| الاسم | النوع | مصدر القيمة |
| --- | --- | --- |
| `LOGO_URL` | String | رابط شعار مراس العلم على نطاق المنصة |
| `CODE` **أو** `RESET_URL` | String | `CODE` للأول والثاني، و`RESET_URL` للثالث فقط |
| `SOCIAL_HEADING` | String | عنوان قسم التواصل، أو قيمة فارغة إذا لم توجد حسابات |
| `SOCIAL_1` | String | أيقونة ورابط أول حساب محفوظ صالح، أو فارغ |
| `SOCIAL_2` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_3` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_4` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_5` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_6` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_7` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_8` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_9` | String | أيقونة ورابط الحساب التالي، أو فارغ |
| `SOCIAL_10` | String | أيقونة ورابط الحساب التالي، أو فارغ |

هذه متغيرات القالب داخل Resend، وليست 13 متغير بيئة تضيفها إلى Railway. لا تنشئ `CODE` و`RESET_URL` معًا في القالب نفسه. ترتيب خانات التواصل مضغوط: إذا أضفت إنستغرام فقط فسيكون في `SOCIAL_1`، وليس في خانة ثابتة خاصة بإنستغرام.

صيغة المتغير في **مصدر HTML** تستخدم ثلاثة أقواس من كل جهة:

```html
<img src="{{{LOGO_URL}}}" alt="مراس العلم">
<span>{{{CODE}}}</span>
<a href="{{{RESET_URL}}}">تعيين كلمة مرور جديدة</a>
<div>{{{SOCIAL_HEADING}}}</div>
<div>{{{SOCIAL_1}}}</div>
```

المثال يوضح الصيغة فقط؛ استخدم ملف القالب الكامل المناسب، ولا تجمع حقول الرموز والاستعادة يدويًا. يحتوي `SOCIAL_1` وما يليه على HTML آمن يُنشئه الخادم للأيقونة والرابط، وليس على رابط خام فقط. لا تستبدلها بروابط حسابات ثابتة في محرر القالب إذا أردت استمرار التحكم فيها من الإدارة. [توثيق متغيرات Resend الرسمي](https://resend.com/docs/dashboard/templates/template-variables).

## إضافة حسابات التواصل من الإدارة

أضف روابطك من إعدادات المنصة / التواصل الاجتماعي، ثم احفظ. القنوات المدعومة: واتساب، إكس، إنستغرام، تيك توك، يوتيوب، تيليغرام، لينكدإن، فيسبوك، سناب شات وثريدز. أدخل رقم واتساب في حقل الرقم، وروابط HTTPS الصحيحة للحسابات الأخرى في حقولها.

- يستهلك الويب والتطبيق والبريد إعدادات التواصل العامة نفسها؛ لا تحتاج إعادة كتابة الحسابات داخل كل قالب.
- تُعرض الحسابات المضافة والصحيحة فقط. لا يُنشئ النظام حسابات وهمية، ولا يملأ الروابط الناقصة بحسابات افتراضية.
- ترفض طبقة التحقق روابط JavaScript، والنطاقات المنتحلة، وبيانات الدخول المضمنة في الرابط، والمنافذ غير المدعومة. يُرمّز محتوى الرابط والتسمية قبل إدخاله في HTML.
- يقرأ تجهيز الرسالة إعدادات التواصل عند إنشاء كل بريد جديد، ولا يخزّن نسخة منها ضمن cache القوالب. طبقة الإعدادات العامة لها تخزين قصير يُبطل عند الحفظ؛ قد تتأخر المزامنة قليلًا بين نسخ الخادم.
- تؤثر الإضافة أو التعديل أو الحذف في **الرسائل التي تُنشأ بعد التغيير**. الرسائل التي وصلت بالفعل إلى صندوق المستلم لا يمكن تحديث روابطها عن بُعد.

## التحقق قبل الاعتماد

### التجربة على جهاز التطوير

يسمح الربط بعنوان HTTP فقط لـ`localhost` أو `127.0.0.1` أو `[::1]` عندما تكون `NODE_ENV=development`؛ روابط التحقق والاستعادة المحلية تُفتح من جهاز التطوير نفسه، وليست روابط صالحة لبقية الطلاب. في هذه الحالة يستخدم الخادم HTML المباشر حتى لو أضفت ID لقالب مستضاف، كي لا ينتقل زر التحقق إلى موقع الإنتاج. تبقى صور الشعار والتواصل على `https://marasalelm.com`، لأن برنامج البريد لا يستطيع جلب صور جهازك المحلي؛ الصور الجديدة تحتاج نشر الأصول على النطاق العام أولًا. في الإنتاج يبقى HTTPS إلزاميًا. تُحدد وجهة البريد من `APP_URL` ثم `NEXT_PUBLIC_SITE_URL` ثم النطاق الافتراضي، وليس من ترويسة Host الواردة مع الطلب.

### نطاق الاختبارات

الاختبارات المحلية تغطي القوالب الثلاثة، إبقاء الصفر الأول في الرمز، أصل رابط الاستعادة وعدد الرموز داخله، تنقية التواصل، اختلاف الإعدادات بين الرسائل، الإرسال المباشر والمستضاف، وحدود المتغيرات ومعالجة أخطاء المزود. ملفات HTML مضمنة في Docker وفي تتبع ملفات مسارات API.

تفحص أداة `scripts/verify-resend-templates.mjs` العرض محليًا عند 320 و390 و760 بكسل، مع تنسيقات الرأس وبدونها، ومع قنوات التواصل وبدونها. تستخدم صور المشروع المحلية وعينات غير حقيقية، وتنتج لقطات في `outputs/resend-templates`.

**هذا ليس اختبار إرسال فعليًا عبر Resend أو اختبارًا داخل Outlook أو Gmail أو Apple Mail.** لم تُنشأ القوالب أو تُنشر في حساب Resend ضمن هذا التوثيق. بعد نشر المنصة وضبط المرسل، اختبر بحسابك: تأكيد البريد، تغيير كلمة المرور، ثم نسيان كلمة المرور. تأكد من وصول الرسائل وسلامة الصور والرموز والروابط في البريد الذي تستخدمه، ومن ظهور حسابات التواصل التي حفظتها. لا تُرسل رمزًا حقيقيًا إلى طرف آخر لغرض المعاينة.
