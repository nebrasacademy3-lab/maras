# قوالب مراس العلم — Resend

ثلاثة قوالب HTML عربية مستقلة للرسائل المستخدمة بالفعل في المشروع. أُنشئت في 6 سبتمبر 2026. لم تُرفع إلى Resend، ولم يُرسل بريد تجريبي، ولم يتغير كود الإرسال الحالي.

| الملف | الاسم / alias المقترح | موضوع الرسالة | المتغيرات |
| --- | --- | --- | --- |
| 01-verify-email.html | meras-verify-email | رمز تأكيد بريدك — مراس العلم | LOGO_URL، CODE |
| 02-change-password.html | meras-change-password | رمز تغيير كلمة المرور — مراس العلم | LOGO_URL، CODE |
| 03-reset-password.html | meras-reset-password | استعادة كلمة مرورك — مراس العلم | LOGO_URL، RESET_URL |

## النسخ إلى Resend

1. افتح Templates ثم Create template، وحدد اسمًا وموضوعًا ومرسلًا من نطاقك الموثّق في Resend. اسم القالب وحده ليس بالضرورة alias؛ استخدم ID الذي تعرضه الخدمة عند الربط، أو اضبط alias صراحة.
2. الصق محتوى ملف HTML كاملًا في محرر القالب أو استورده بالطريقة التي يدعمها محرر HTML. هذا الاستيراد موثق من Resend؛ راجع المظهر والمتغيرات بعده.
3. ارفع الشعار الموجود في `public/brand/logo-light-hq.png` إلى مكتبة الصور في محرر Resend، وانسخ رابطه العام HTTPS. أضف متغيرًا اسمه `LOGO_URL` من النوع string واجعل رابطه هو القيمة الافتراضية في كل قالب. الشعار عالي الدقة ونسبة عرضه محفوظة. بديلًا: استبدل `{{{LOGO_URL}}}` في HTML برابط الصورة المرفوعة نفسه واحذف تعريف المتغير.
4. القالبان الأول والثاني: عرّف `CODE` كـ string دون قيمة افتراضية. الثالث: عرّف `RESET_URL` كـ string دون قيمة افتراضية. لا تضع رمزًا تجريبيًا أو رابطًا ثابتًا كقيمة افتراضية في قالب منشور.
5. أرسل اختبارًا إلى بريدك من حسابك، ثم انشر القالب بـ Publish. التعديلات التالية تحتاج نشرًا جديدًا. لا يمكن إرسال قالب لا يزال مسودة.

رابط الشعار الحالي في الموقع يعيد PNG بنجاح، لكنه يحمل `Cross-Origin-Resource-Policy: same-origin`؛ لذا قد تمنعه معاينات البريد الخارجية. رفع النسخة نفسها إلى Resend يتجنب الاعتماد على هذه السياسة، دون إضعاف إعدادات الموقع. لم ننشئ رابط CDN وهميًا أو نعدل الحماية. قد يحجب بعض المستلمين الصور افتراضيًا؛ يبقى النص والرمز والروابط ظاهرين مع نص بديل للشعار.

## الربط المطلوب في المنصة

**الحفظ في Resend وحده لا يغير الرسائل الحالية.** الدالة `lib/transactional-email.ts` ترسل `text` مباشرة. يجب أن يستخدم طلب الإرسال القالب المنشور ومتغيراته بدل النص الحالي. هذه المهمة توفر القوالب فقط، ولم تعدل إرسال رموز الأمان.

مثال جسم طلب `POST https://api.resend.com/emails`، بعد إعداد القيمة الافتراضية لـ LOGO_URL:

```json
{
  "from": "مراس العلم <YOUR_VERIFIED_SENDER>",
  "to": ["RECIPIENT_EMAIL"],
  "subject": "رمز تأكيد بريدك — مراس العلم",
  "template": {
    "id": "PUBLISHED_TEMPLATE_ID_OR_CONFIGURED_ALIAS",
    "variables": { "CODE": "012345" }
  }
}
```

المثال لا يُرسل كما هو؛ المرسل والمستلم وID متغيرات خاصة بحسابك، والرمز للتوضيح فقط. عند الاستعادة استخدم القالب الثالث و`variables: { RESET_URL: resetUrl }`. لا تجمع `template` مع `text` أو `html` أو `react` في طلب الإرسال نفسه. احفظ مفتاح Resend في الخادم فقط، واحتفظ بترويسة idempotency الحالية ومعالجة إخفاق الإرسال.

مصادر القيم الصحيحة في المشروع:

- `lib/email-verification.ts`: الرمز `code` نفسه، مع اختيار القالب حسب `purpose`؛ مدة كلا الرمزين 10 دقائق، مرة واحدة، ولا يُطلب التحقق مجددًا قبل كل شراء.
- `app/api/auth/forgot-password/route.ts`: رابط HTTPS الكامل بنفس `origin` و`token` المُنشأين في الخادم؛ مدة الرابط 15 دقيقة، مرة واحدة. لا تنشئ رمزًا آخر داخل القالب.
- لا تُمرر HTML من المستخدم كمتغير. تحقّق أن CODE سلسلة من ستة أرقام للحفاظ على الصفر الأول. يجب أن يكون RESET_URL صادرًا من الخادم وعلى أصل الموقع الموثوق ومسار reset-password، لا رابطًا يُرسله المستخدم. روابط HTML تحتاج ترميزًا صحيحًا عند بنائها يدويًا.
- لا تستخدم fallback للرموز وروابط الأمان، ولا تضع الرمز في موضوع الرسالة أو نص المعاينة المسبق. نصوص المدد في القوالب تطابق المصدر الحالي؛ حدّثها إذا تغيرت مدد الخادم مستقبلًا.
- روابط المنصة والدعم والخصوصية ثابتة على النطاق الحالي `https://marase.up.railway.app`. استبدل هذا الأصل في القوالب الثلاثة عند الانتقال إلى نطاق آخر.

## التحقق وحدوده

يعتمد التصميم على جداول وتنسيقات مضمنة وخطوط قياسية، مع عرض بديل لـ Outlook ونص HTML حقيقي للرمز؛ لا JavaScript أو نماذج أو SVG أو خطوط خارجية أو حركات. قد تختلف الزوايا والخطوط والوضع الداكن حسب تطبيق البريد؛ لا يمكن فرض مظهر واحد على كل عميل.

أداة `scripts/verify-resend-templates.mjs` تفحص محليًا المتغيرات، واتجاه العربية والأرقام، والروابط، وعدم تجاوز عرض 320 و390 و760 بكسل، مع CSS الرأس وبدونه. تستخدم شعارًا من الملف المحلي وعينات غير حقيقية، وتنتج لقطات داخل `outputs/resend-templates`. هذا ليس اختبار تسليم عبر Resend أو اختبارًا فعليًا في Outlook/Gmail/Apple Mail. اختبر صندوق بريدك بعد الاستيراد والنشر قبل اعتماد القوالب.
