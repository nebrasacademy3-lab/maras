# خدمة فحص مرفقات مراس

خدمة الفحص تعمل منفصلة عن الويب وتشغّل ClamAV. كتابة رابط وتوكن في متغيرات الويب لا تنشئ الخدمة. العنوان `http://scanner:3001/scan` يخص Docker Compose المحلي؛ في Railway يلزم عنوان خدمة Railway الخاصة.

## إعداد Railway

1. أضف خدمة مستقلة من مستودع مراس في **نفس المشروع ونفس البيئة** التي يعمل فيها الويب، وسمّها `scanner`. استخدم الملفات المحدثة في هذا المجلد.
2. في إعدادات الخدمة اضبط:

   | الحقل | القيمة |
   | --- | --- |
   | Root Directory | `/services/scanner` |
   | Builder | `Dockerfile` |
   | Dockerfile Path | `Dockerfile` |
   | Start Command | `/usr/bin/tini -g -- /opt/meras-scanner/entrypoint.sh` |
   | Healthcheck Path | `/ready` |
   | Healthcheck Timeout | `900` ثانية |
   | Restart Policy | `On Failure` |

   أزل أي أمر بناء أو بدء أو Pre-deploy موروث من خدمة الويب، وأوقف Serverless/Sleep للخدمة حتى يبقى الفاحص جاهزًا. لا تستخدم `./scripts/start-railway.sh` أو `/api/health` مع الفاحص. راجع الإعدادات الفعلية في تفاصيل النشر.
3. أضف Volume على المسار `/var/lib/clamav` لحفظ تواقيع الفحص. خصص ذاكرة مناسبة للمحرك؛ ابدأ بذاكرة 2 GB أو أكثر وراجع استهلاكها. يبدأ المشغّل بتهيئة ملكية المجلد ثم يشغّل جميع الخدمات بحساب `clamav` دون صلاحيات root.
4. في Variables لخدمة **scanner** أضف `PORT=3001` و`MALWARE_SCAN_TOKEN`. أنشئ سرًا جديدًا مرة واحدة بالأمر التالي وانسخ الناتج إلى هذا المتغير؛ لا ترسله بالمحادثة ولا تضفه للمستودع:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

5. في Variables لخدمة **الويب**، عند تسمية الفاحص `scanner`، يمكن لصق القيم التالية. هذه مراجع Railway تلقائية إلى سر الخدمة ونطاقها الخاص:

   ```env
   MALWARE_SCAN_URL=http://${{scanner.RAILWAY_PRIVATE_DOMAIN}}:3001/scan
   MALWARE_SCAN_TOKEN=${{scanner.MALWARE_SCAN_TOKEN}}
   FILE_SCAN_SCHEDULER_ENABLED=true
   ```

   إذا كان اسم خدمة الفحص مختلفًا، استبدل `scanner` في المرجعين بالاسم الفعلي. إذا كان لديك عامل ملفات منفصل، يحتاج إعدادات الاتصال نفسها ووصولًا إلى نفس التخزين وقاعدة البيانات.
6. انتظر نجاح نشر **scanner** وجاهزيته، ثم أعد نشر الويب لتطبيق المتغيرات. تنزيل التواقيع وتحميلها أول مرة قد يستغرق دقائق. بعد نجاح اختبار الاتصال في إدارة الملفات، أعد محاولة الملفات العالقة.

لا تحتاج الخدمة نطاقًا عامًا ولا TCP Proxy؛ لا تعرض منفذ ClamAV على الإنترنت. يقبل الخادم IPv4 وIPv6 لأن بعض بيئات Railway القديمة تستخدم IPv6 فقط. `GET /ready` عام ويعيد `{"ok":true}` فقط بعد فحص عينة ثابتة بمحرك ClamAV؛ لا يكشف الأسرار ولا يقبل ملفات. يبقى `POST /scan` و`GET /health` محميين بالتوكن.

## إعدادات Railway القديمة

يوجد `railway.json` مستقل في هذا المجلد لدعم الخدمات القائمة التي تستخدم Config as Code. لتلك الخدمات فقط، اضبط مسار Railway Config File على `/services/scanner/railway.json`؛ المسار مستقل عن Root Directory. لا تستخدم ملف `/railway.json` الرئيسي لأنه يخص الويب.

بحسب توثيق Railway الحالي، ملفات Config as Code القديمة متوقفة للخدمات الجديدة وينتهي دعم الخدمات القائمة في 1 ديسمبر 2026. لذلك خطوات الإعداد في لوحة Railway أعلاه هي المسار الأساسي، ولا يكفي الاعتماد على الملف وحده.

## تشخيص استمرار الفشل

- عدم العثور على `scanner` أو `ENOTFOUND`: الرابط القديم الخاص بـ Docker أو اسم الخدمة خاطئ؛ تحقق من النطاق الخاص ووجود الخدمتين في المشروع والبيئة نفسيهما.
- رفض الاتصال: تحقق من جاهزية الفاحص، `PORT=3001`، ومسار `/scan`، واستخدام النسخة التي تدعم IPv6.
- `401` أو `403`: التوكن غير متطابق بين الفاحص والويب؛ استخدم مرجع Railway أعلاه ثم أعد نشر الويب.
- `503` أو فشل `/ready`: افتح Deploy Logs للفاحص. إذا ظهرت `No signature database is available`، راجع اتصال freshclam بمصدر التواقيع وصلاحية القرص. إذا كانت المشكلة حد تنزيل أو مهلة من المصدر، احترم زمن إعادة المحاولة الظاهر في السجل؛ إعادة إنشاء القرص مرارًا تعيد التنزيل.
- `Permission denied` في `/var/lib/clamav`: استخدم Dockerfile والمشغّل المحدثين؛ لا تفرض مستخدمًا مختلفًا في إعدادات Railway.
- توقف الخدمة أو نفاد الذاكرة: راجع سجل الخروج وMetrics وزد الذاكرة عند ثبوت الحاجة.
- فقدان الملف القديم من التخزين: إصلاح الاتصال لا يعيد بايتات حُذفت من القرص المؤقت. تحقق من Volume الرفع أو التخزين الخارجي واستعد النسخة الاحتياطية عند الحاجة، مع إبقاء فحص الملف إلزاميًا.

إذا فشل تحديث التواقيع مع وجود قاعدة محفوظة، تحاول الخدمة استخدام القاعدة الحالية؛ لا تصبح جاهزة إلا بعد أن يقبلها ClamAV وينجح فحص فعلي. توقف أي عملية أساسية ينهي الحاوية ليعيد Railway تشغيلها. في غياب قاعدة قابلة للاستخدام أو عند فشل الفحص تظل التنزيلات محجوبة.

## البروتوكول والاختبار المحلي

يقبل `POST /scan` حتى 100 MB بحد طلبين متزامنين، وترويسة `x-content-sha256`. يتحقق من البصمة ثم يفحص نفس البايتات عبر INSTREAM. الملفات المصابة أو المشفرة أو المتجاوزة لحدود الأرشيف لا تمنح إذن تنزيل. عامل مراس يعيد المحاولة بتأخير متدرج، ويمكن تشغيل دفعة يدويًا بواسطة `npm run files:scan:once` داخل بيئة الويب المناسبة.

اختبارات الخادم:

```bash
node --test tests/scanner-railway.test.mjs tests/file-scan-security.test.mjs
```

هذه الاختبارات المحلية لا تثبت نجاح نشر Railway أو استرجاع ملفات قديمة من تخزين الإنتاج. يلزم التحقق من سجلات النشر ونتيجة اختبار اتصال الإدارة في بيئتك.
