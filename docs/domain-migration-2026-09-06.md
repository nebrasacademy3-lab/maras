# نقل مراس العلم إلى marasalelm.com

النطاق الأساسي المعتمد في كود SEO وأمثلة نشر Railway وإعدادات API وبناء EAS للتطبيق هو `https://marasalelm.com`. بقي `localhost` في مثال التطوير المحلي فقط، وبقيت التقارير التاريخية كما كانت وقت كتابتها. لا يتغير معرّف حزمة التطبيق `sa.merasalelm.app` أو مخطط العودة `merasalelm://` عند تغيير نطاق الموقع.

## ما تم التحقق منه

في 6 سبتمبر 2026 بتوقيت الرياض، فُحص الموقع العام قراءة فقط:

- الصفحة الرئيسية: HTTP 200 ورابط canonical إلى `https://marasalelm.com`.
- `/robots.txt`: يسمح بالصفحات العامة ويشير إلى خريطة النطاق الجديد.
- `/sitemap.xml`: HTTP 200، وجميع الأصول داخل الخريطة هي `https://marasalelm.com`.
- HTTPS: شهادة موثوقة للنطاق واتصال TLS 1.3. تاريخ نهاية الشهادة التي رُصدت هو 4 ديسمبر 2026، 21:36:42 UTC. لم نُصدر شهادة أو نغيّر إعدادات DNS/TLS.
- اختبارات SEO المعزولة: 18 ناجحة. اختبار HTTP على البناء الإنتاجي المحلي بإعداد النطاق الجديد: 5 ناجحة. فحوص توافق اتصال التطبيق: 8 ناجحة.
- حلّ إعداد Expo الفعلي دون متغيرات تجاوز أعاد API جديدًا، و`applinks:marasalelm.com` في iOS، و`marasalelm.com` في intent filters لأندرويد.

هذه فحوص محددة وليست اختبارًا لكل حساب أو خدمة خارجية.

## إعدادات المالك عند النشر

1. في Railway، اجعل القيمتين التاليتين متطابقتين وقت البناء والتشغيل، ثم أعد نشر المشروع؛ متغيرات `NEXT_PUBLIC_` تدخل في بناء المتصفح:

   ```env
   APP_URL=https://marasalelm.com
   NEXT_PUBLIC_SITE_URL=https://marasalelm.com
   ```

2. في Google Cloud، أضف عنوان العودة الكامل التالي إلى Web OAuth client، وراجع النطاق المعتمد في شاشة الموافقة:

   ```text
   https://marasalelm.com/api/auth/oauth/google/callback
   ```

3. في Apple Services ID، أضف النطاق `marasalelm.com` وعنوان العودة التالي، دون تغيير معرف الخدمة أو مفاتيحها لمجرد تغيير النطاق:

   ```text
   https://marasalelm.com/api/auth/oauth/apple/callback
   ```

4. وثّق نطاق إرسال تملكه في Resend حسب سجلات DNS التي يعرضها حسابك، ثم اضبط `EMAIL_FROM` على عنوان بذلك النطاق. ظهور الموقع عبر HTTPS لا يثبت توثيق الإرسال بالبريد. راجع كذلك مصدر الإرسال في Apple Private Email Relay إذا استخدمت Apple Hide My Email. [دليل Resend الرسمي](https://resend.com/docs/dashboard/domains/introduction).

5. أعد بناء نسختي التطبيق؛ التطبيقات المثبتة سابقًا لا تتغير عناوينها بملف Git أو بإعادة نشر الويب. راجع متغيرات EAS المحفوظة خارجيًا بحيث لا تتجاوز القيم الجديدة بقيم قديمة. اختبر التسجيل وتأكيد البريد واستعادته وفتح الدروس على النسخة الجديدة.

6. راجع عناوين webhook/عودة الدفع المسجلة خارج المنصة، وأي روابط حملات أو ملفات إدارة محفوظة كعناوين مطلقة. لا تغيّر معرفات عمليات الدفع القائمة. لم نعدّل بيانات قاعدة الإنتاج أو روابط المستخدمين القديمة آليًا.

7. تحقّق من ملكية الدومين الجديد في Search Console وأرسل `https://marasalelm.com/sitemap.xml`، مع مراجعة نقل النطاق القديم. نتائج البحث قد تتذبذب خلال إعادة الفهرسة ولا توجد ضمانات لترتيب محدد. [دليل Google الرسمي لنقل الموقع](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes).

## أمور رُصدت وتحتاج إعدادًا خارجيًا/بيانات التوقيع

- النطاق `www.marasalelm.com` والنطاق السابق على Railway يعيدان HTTP 200 بدل التحويل إلى النطاق الأساسي. يوصى بتحويل دائم لصفحات الويب مع الحفاظ على المسار ومعاملات البحث. يجب استثناء/ترحيل API وOAuth وwebhooks وفق خطة، لأن تحويلها عشوائيًا قد يقطع التطبيقات القديمة أو طلبات POST أو ملفات الجلسة. لم يُفعّل تحويل شامل في هذه المهمة.
- المساران `/.well-known/assetlinks.json` و`/.well-known/apple-app-site-association` يعيدان 404 على النطاق الجديد وقت الفحص. إعداد host داخل التطبيق وحده لا يفعّل الروابط الموثقة على نظام التشغيل: يلزم ملف Android ببصمات شهادة توقيع التطبيق الصحيحة، وملف Apple بمعرّف فريق التطبيق الصحيح. هذه ليست مفاتيح يجوز اختراعها. تخص هذه النقطة فتح رابط HTTPS مباشرة بالتطبيق؛ تدفق OAuth الحالي يعود عبر مخطط التطبيق المخصص ويختلف عنها. [Android App Links](https://developer.android.com/training/app-links/configure-assetlinks)، [Apple Associated Domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains).

لم يُنفذ نشر، أو تعديل DNS، أو إعداد لحسابات Google/Apple/Resend/Tap، أو تغيير لملفات الأسرار المحلية ضمن هذا العمل.
