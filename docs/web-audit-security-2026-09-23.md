# تنفيذ عناصر تدقيق الويب — 23 سبتمبر 2026

النص المرفق يسرد أسماء اختبارات تشخيصية عامة، ولا يتضمن عناوين صفحات أو عناصر فاشلة أو دليلًا بأن كل بند مشكلة قائمة. جرى التحقق من البنود الأمنية المطلوبة على نسخة إنتاجية محلية بقاعدة اختبار اصطناعية؛ لا يمثّل ذلك تدقيقًا للنطاق المنشور أو شهادة امتثال شاملة.

| البند | الحالة الفعلية |
| --- | --- |
| WebMCP في النماذج | أضيفت `toolname` و`tooldescription` و`toolparamdescription` إلى نموذج البحث العام فقط. بقي الإرسال بيد المستخدم وطلب البحث من نوع GET. لم تُعلن نماذج الدخول أو الدفع أو الإدارة كأدوات للوكلاء. Chrome المحلي لا يعرّض `document.modelContext` في إعداداته الحالية؛ التوافق مع متصفح يدعم المسودة يحتاج اختبارًا فيه. |
| أدوات WebMCP المسجلة | البحث العام هو الأداة التصريحية الوحيدة. لم نسجّل أدوات JavaScript امتيازية أو نفتح إجراءات خاصة للوكيل. تعداد الأدوات في تقرير المتصفح تشخيصي، وليس شرطًا بأن يكون له عدد موجب. |
| `ai-catalog.json` وARD | مساران صالحان على `/ai-catalog.json` و`/.well-known/ard.json` يقدمان بيانات هوية عامة فقط و`entries: []`. جرى التحقق من الاستجابة الفعلية بمخططي المسودتين الرسميين. لا ننشر أدوات الحساب الخاصة كخدمة MCP مزعومة. تتوقف الإتاحة عند تعطيل الفهرسة وفي التطوير، وتظهر روابط الاكتشاف في تخطيط الويب عند السماح بالفهرسة. |
| HTTP → HTTPS | تحويل 308 لاسم المضيف العام المضبوط صراحة عند ورود `X-Forwarded-Proto: http` من الحافة الموثوقة، مع حفظ المسار والاستعلام. ظهر `308` ووجهة HTTPS في الاختبار الإنتاجي المحلي. يلزم ضبط الحافة نفسها لتحويل HTTP والتحكم في الترويسة. |
| COOP ومنع تضمين الصفحات | `Cross-Origin-Opener-Policy: same-origin` و`X-Frame-Options: SAMEORIGIN` و`frame-ancestors 'self'` ظاهرة في استجابات الإنتاج. |
| CSP ضد XSS | تحوّل `script-src` من السماح العام لـ`unsafe-inline` إلى رمز nonce عشوائي لكل طلب و`strict-dynamic`، مع `script-src-attr 'none'` ومنع `unsafe-eval` في الإنتاج. وجدت تجربة الصفحة 19 نصًا تنفيذيًا بالرمز الصحيح، مع نص JSON-LD غير تنفيذي وحده. بقي `style-src 'unsafe-inline'` لتوافق الأنماط الحالية؛ يجب فصل الأنماط المضمنة قبل إزالته. |
| HSTS و`preload` | تصل `max-age=31536000; includeSubDomains` في إنتاج HTTPS فقط. لم نضف `preload`: ذلك قرار التزام طويل على كل النطاقات الفرعية ولا يُتخذ دون جرد شهاداتها وطرق التراجع. عدم وجود `preload` لا يعني غياب HSTS. |
| Trusted Types | أضيف `require-trusted-types-for 'script'` بوضع **Report-Only** في الإنتاج. رصد Chrome عمليات مخالفة فعلية في الصفحات الأربع المختبرة، لذلك فرض التوجيه الآن سيعطل وظائفها. يلزم معالجة مواضع DOM في React/Next والتبعيات، ثم إعادة الفحص قبل فرضه. لا يُحسب الرصد حماية إلزامية من DOM XSS. |
| مكتبات JavaScript | سرد المكتبات بند جرد تشخيصي؛ لم يتضمن النص المرفق نسخة ضعيفة محددة. لا يصح الادعاء بمعالجة ثغرة تبعية بلا اسم وإصدار ودليل. |
| الوصول | أضيف رابط تخطي للمحتوى وإصلاح دلالات جدول الإدارة. الفحص الآلي الموجّه لثماني صفحات وحالتين تفاعليتين بلا مخالفات للقواعد المدرجة، وفحص Tab/Enter نجح على أربعة تخطيطات. الفيديو يحتاج ترجمة نصية حقيقية ومراجعة يدوية؛ لم نضف مسار ترجمة فارغًا. |

## التحقق

- اكتمل `next build` وفحص التنسيق دون أخطاء، ونجحت **17/17** حالة اختبار في اكتشاف الوكلاء وCSP والنقل والوصول.
- على خادم الإنتاج المحلي: `GET /` و`/login` أعادا CSP برمز مختلف لكل طلب؛ `GET /ai-catalog.json` و`/.well-known/ard.json` أعادا 200 وبنية البيان المتوقعة؛ `Host: maras-qa.example` مع `X-Forwarded-Proto: http` أعاد 308 إلى HTTPS؛ ترويسة HTTPS أعادت HSTS.
- في Chrome، فتحت الصفحة الرئيسية والمواد والدخول والإدارة بحالة 200، دون أخطاء JavaScript أو مخالفات CSP **مفروضة** أثناء التشغيل العادي. حقن معالج `onclick` تجريبي مُنع فعليًا (`script-src-attr`, `enforce`) ولم ينفذ. ظهرت مخالفات Trusted Types في وضع الرصد فقط، وهي سبب عدم فرضه الآن. التفاصيل الآلية المحلية في `output/playwright/web-audit-production-20260923.json`.

تفصيل الاكتشاف وحدوده في [توثيق الوكلاء](agent-discovery-2026-09-23.md)، وإعدادات النشر في [مراجعة HTTP](http-security-review-2026-09-23.md)، ودليل فحص الوصول في `output/playwright/accessibility-20260923/README.md`.
