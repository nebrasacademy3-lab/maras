# النسخ المشفّر والاستعادة المعزولة — 19 سبتمبر 2026

## النطاق

الأدوات في `scripts/recovery.mjs` تنشئ نسخة تطبيق من قاعدة PostgreSQL واحدة وملفات التخزين **المحلي** أثناء توقف الكتابات والعوامل. لا تدعي هذه الدفعة نسخ S3 أو الاستعادة الزمنية المستمرة PITR، ولا نسخ أدوار العنقود وtablespaces أو مفاتيح مدير الأسرار. ترفض النسخة المحلية السجلات التي تصرح بمزود تخزين غير محلي بدل اعتبارها نسخة مكتملة. الملفات القديمة التي لا تحفظ المزود تحتاج تدقيقًا منفصلًا.

لا يغير هذا العمل `main` أو Railway، ولا يفعل تغيير البريد أو أي مزود مدفوع. نجاح التجربة الاصطناعية لا يعتمد بيانات الإنتاج أو حجمها أو أذونات مزودها.

## ضمانات التنفيذ

- `pg_dump` بصيغة custom ومن لقطة PostgreSQL مشتركة مع جرد الجداول. يلزم إصدار رئيسي مطابق للخادم؛ لا يوجد fallback إلى نسخة أقدم من أدوات PostgreSQL.
- تدفق قاعدة البيانات مباشرة إلى تشفير AES-256-GCM، ومفتاح فرعي مشتق بـHKDF وملح وnonce عشوائيين لكل ملف. بيان النسخة وأسماء مفاتيح التخزين مشفرة أيضًا. يرتبط كل ملف تشفيريًا بمعرف النسخة ومفتاح الكائن لمنع تبديل الملفات.
- ملف المفتاح خاص (0600)، ولا تقبل روابط رمزية/صلبة له. ترفض واجهة الأوامر وضع ملف المفتاح داخل مجلد التخزين أو النسخة قبل الاتصال بقاعدة البيانات، ولا تسجل روابط الاتصال أو أخطاء SQL الخام أو مفاتيح الخدمات.
- رفض traversal والمسارات الملتبسة والروابط الرمزية والملفات ذات الروابط الصلبة المتعددة، وحدود لحجم البيان وعدد الملفات وحجمها الكلي. ملفات التخزين تُراجع قبل النسخ وبعده لكشف التغير. هذا **ليس قفلًا شاملًا على جميع الكتّاب**: إيقاف الكتابات والعوامل شرط تشغيلي لا يحل محله متغير الإقرار.
- ملف `COMPLETE` يكتب ويزامن أخيرًا بعد ملفات النسخة. عملية تنتهي فجأة قبل ذلك تترك نسخة غير معتمدة؛ لا تتعامل معها كنسخة صالحة.
- الاستعادة تتحقق من المصادقة والطول وSHA-256 لكل ملف في مساحة خاصة قبل تنفيذ `pg_restore`. لا تمرر بايتات مفكوكة التشفير إلى SQL قبل نجاح التحقق النهائي.
- الاستعادة إلى قاعدة **جديدة فقط** باسم `maras_restore_...` على اتصال loopback صريح. لا يوجد `DROP DATABASE` أو `--clean` في أداة الاستعادة، ولا استبدال لمجلد قائم. يمكن استعمال نفق إلى خادم استعادة معزول، وليس نفقًا إلى الإنتاج.
- `pg_restore --single-transaction --exit-on-error`؛ إيقاف عند أي خطأ أو تحذير من أدوات PostgreSQL. تقارن أسماء الجداول وأعداد صفوفها بجرد النسخة. النسخة المستعادة تبقى `ALLOW_CONNECTIONS false`، ولا تُشغّل أي عامل أو خدمة تلقائيًا.
- فشل ما بعد إنشاء القاعدة يبقيها للمراجعة؛ لا يحذف أي قاعدة موجودة. العلامة `MARAS_RECOVERY_INCOMPLETE` تميز استعادة لم تعتمد بعد، و`MARAS_RECOVERY_VERIFIED_OFFLINE` تميز استعادة تحققت وبقيت معزولة. الانهيار القسري قد يترك مساحة مؤقتة خاصة وقاعدة جديدة تحتاج فحصًا يدويًا؛ لا تدعي الأداة تنفيذ تنظيف عند SIGKILL.

## أوامر المشغل

تعمل الأدوات على Linux/POSIX مع Node.js 22 و`pg_dump` و`pg_restore` من الإصدار الرئيسي نفسه للخادم. لا تقرأ `.env` تلقائيًا. استخدم حساب قاعدة مخصصًا وبيئة تشغيل معزولة، ولا تضع كلمة المرور في سطر الأوامر أو سجل طرفية مشترك. جهّز مسارات مطلقة موجودة للآباء، خاصة بالمشغل، ومفتاحًا عشوائيًا 32 بايت أو 64 محرف hex في ملف 0600 من مدير الأسرار.

للنسخ، يزود المشغل هذه المتغيرات عبر مدير الأسرار/الجلسة الآمنة:

```text
BACKUP_DATABASE_URL       اتصال المصدر الصريح؛ TLS متحقق خارج loopback
RECOVERY_KEY_FILE         ملف المفتاح الخاص، خارج مجلد النسخة والتخزين
RECOVERY_UPLOAD_DIR       جذر ملفات التخزين المحلي المتوقف عن الكتابة
RECOVERY_BUNDLE_DIR       مسار جديد لا يقع داخل التخزين
RECOVERY_RELEASE_SHA      SHA كامل للنسخة المنشورة المطابقة للقطة
RECOVERY_STORAGE_MODE     local
RECOVERY_WRITES_PAUSED    true، بعد الإيقاف الفعلي وليس بديلًا عنه
RECOVERY_PG_BIN_DIR       اختياري؛ مجلد أدوات PostgreSQL المطابقة
```

```sh
node scripts/recovery.mjs backup
```

للتحقق والاستعادة، استخدم مفتاح النسخة نفسه، ومسار مجلد نسختها، ومجلد استعادة جديد:

```text
RESTORE_ADMIN_URL         اتصال loopback إلى خادم استعادة منفصل
RESTORE_DATABASE_NAME    maras_restore_متبوعًا بـ8–40 محرفًا من a-z0-9_
RECOVERY_UPLOAD_DIR       مجلد استعادة جديد؛ تنتج الملفات داخل objects/
RECOVERY_TRUSTED_BACKUP   true، بعد التحقق من المصدر وحفظ البصمة خارج الحزمة
```

```sh
node scripts/recovery.mjs restore
```

لا تستعد أرشيفًا من مصدر غير موثوق: مصادقة التشفير تثبت امتلاك المفتاح وسلامة الحزمة، لكنها لا تجعل SQL القادم من مصدر خبيث آمنًا. لا توجد استعادة تلقائية إلى قاعدة التطبيق الحالية أو نشر تلقائي.

## إجراء الترحيل والرجوع

قبل الترحيل: أوقف ingress والكتابات وكل نسخ العمال، وثبت SHA للصورة المنشورة، وخذ نسخة قاعدة/تخزين متوافقة ونسخة مستقلة من أسرار AI/MFA والتوقيع. احتفظ بالحزمة المشفرة وبصمتها في مخزن منفصل محدود الوصول، وتحقق من سياسة الاحتفاظ والتشفير لدى المخزن. انقلها إلى خادم استعادة معزول وجرّب المفتاح الحقيقي بموافقة المشغل؛ لم ينفذ ذلك على الإنتاج في هذه الدفعة.

بعد نجاح الاستعادة: القاعدة مقفلة. يراجع المشغل التعليق و`RECOVERY.json`، ثم يسمح باتصالات **بيئة الفحص فقط**. راجع المستخدم الإداري، وعزل حسابي طالبين، والفاتورة وحقوق الوصول والتقدم وحالة الحجر وبايتات الملفات. استعد مفاتيح التطبيق الصحيحة من مدير الأسرار، وأبق مزودات البريد والدفع والإشعارات معزولة كي لا يعاد إرسال عمليات حقيقية. أدوار قاعدة البيانات والمنح لا تستعاد بهذه الحزمة ويجب إعادة ضبطها وفق أقل الصلاحيات.

لا تشغل عامل التنظيف على النسخة المنقولة قبل مراجعة بصمات مواقع التخزين. تُحفظ عقود التنظيف والرفع كما كانت، ولا يعاد توجيهها آليًا إلى مخزن جديد. راجع الجلسات المستعادة وسياسة إبطالها قبل استقبال حركة حقيقية. لا تغيّر أسرار فك تشفير AI/MFA بصورة عشوائية؛ فهي لازمة لقراءة البيانات المشفرة السابقة.

إذا فشل الترحيل قبل التثبيت، تحقّق من rollback للمعاملة. إذا ثبت الترحيل ثم احتجت الرجوع، **لا تشغّل كودًا قديمًا على مخطط جديد ولا تخمّن SQL عكسيًا**: استعد لقطة ما قبل الترحيل في قاعدة ومسار ملفات جديدين، وشغّل صورة SHA السابقة في البيئة المعزولة، ثم حوّل الاتصال وحركة المرور فقط بعد القبول. احتفظ بالمصدر الأصلي مغلقًا للتحقيق. الكتابات التي حدثت بعد اللقطة تحتاج خطة مصالحة خاصة قبل أي تحويل؛ لا يُوعَد برجوع بلا فقد لمجرد وجود نسخة.

## الدليل الآلي

- `tests/recovery-bundle.test.mjs`: تشفير تدفقي، ملفات فارغة وكبيرة، مفتاح خاطئ، تبديل السياق، تلف وتقصير/تمديد الغلاف، حدود الحجم، أخطاء التدفق، الملفات الموجودة، الأذونات، الروابط، traversal، بيان خبيث، TLS، وأسماء قواعد الاستعادة.
- `tests/recovery-preflight.test.mjs`: رفض تضمين ملف المفتاح، ورفض إخفاء موقعه عبر رابط رمزي، واختبار واجهة الأوامر للتأكد من الرفض قبل الاتصال وعدم تسجيل بيانات الاتصال.
- `scripts/qa-recovery.mjs`: عشر مجموعات على PostgreSQL حقيقي وملفات محلية اصطناعية. تنشئ مخطط التطبيق حتى 0037، ثم تنسخه وترقيه إلى 0039، وتستعيد اللقطة القديمة وتقارن **كل صف في كل جدول** والملفات، وتتحقق من قيود الملكية والحجر ومن إمكانية الترقية مجددًا. كما تختبر نسخة المخطط الحالي بعقود التنظيف والرفع، ورفض التلف قبل إنشاء القاعدة، وفشل أرشيف SQL مصادق لكنه غير صالح، وعدم المساس بالمصدر أو الوجهات الموجودة.
- Workflow `Recovery acceptance` يحتفظ بتقرير `.data/qa-recovery-report.json` فقط. لا يرفع النسخ أو المفاتيح أو الملفات المؤقتة. نتيجة GitHub المرتبطة بـSHA هي مرجع القبول؛ لا تعد إضافة workflow وحدها نجاحًا.
