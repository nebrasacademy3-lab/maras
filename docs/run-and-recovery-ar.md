# التشغيل والتحقق والاستعادة
## التشغيل
يتطلب الويب Node.js 22.13 أو أحدث، PostgreSQL، وتخزينًا دائمًا، وخدمة ClamAV المرفقة. استخدم npm ci ثم إعداد متغيرات .env.example دون نسخ أسرار إنتاج إلى بيئة الاختبار. شغّل npm run db:migrate، ثم npm run build وnpm start. ملف STAGING_AR.md يشرح تشغيل البيئة المعزولة الكاملة.

العامل npm run files:scan يعالج قائمة الملفات. يوجد أيضًا عامل دوري داخل الويب مع قفل يمنع تكرار معالجة الملف نفسه. لا تعطل فحص التنزيل لتجاوز خطأ مزود الفحص؛ أصلح الخدمة ثم أعد معالجة الطابور من إدارة فحص الملفات.

للاختبار المحلي على Windows دون Docker: npm run qa:database، ثم في جلسة أخرى npm run qa:seed وnpm run qa:web. البيانات والأسرار الاصطناعية محفوظة تحت .data المستثنى من الحزم. لا تستخدم هذه البرامج على إنتاج؛ تتحقق البرامج من loopback واسم قاعدة الاختبار. لا تُشغّل خدمات الاختبار على واجهات شبكة عامة.

## إعدادات الخدمات
- مراس AI: ضع سر تشفير ثابتًا محفوظًا في مدير أسرار. عند تغييره قد تحتاج إعادة إدخال مفاتيح الخدمة. لوحة أدوات مراس تميّز أخطاء التشفير والاعتماد والحصة والفوترة والنموذج والاتصال، وتختبر التوليد الفعلي لكل خدمة.
- التوفر والتنبيهات: سجّل أجهزة Push وبيانات مزودها، وفعّل العامل الدوري. حالة الإرسال ومحاولاته ظاهرة في الإدارة. اختبر بإشعار طالب اصطناعي قبل أي إرسال حقيقي.
- المشتريات: راجع docs/revenuecat-setup-ar.md.
- البحث: راجع دليل SEO ضمن docs وتقارير verification. طبّق إعدادات Search Console وBing/IndexNow على النطاق الحقيقي فقط، وأبق بيئة الاختبار غير مفهرسة.

## النسخ الاحتياطي
احفظ نسخة PostgreSQL مشفرة بصيغة pg_dump المخصصة مع نسخة متوافقة زمنيًا من التخزين الدائم. خزّن أسرار تشفير AI/MFA ومفاتيح مزودات الدفع منفصلة في مدير أسرار؛ نسخ قاعدة البيانات وحدها لا يكفي لفك البيانات المشفرة. حدّد سياسة احتفاظ وجدول نسخ واختبر الاستعادة دوريًا.

عند الاستعادة: أوقف عمليات الكتابة والعوامل، استعد القاعدة والتخزين إلى بيئة منفصلة، ثم طبّق الترحيلات المطلوبة. تحقق من مستخدم إداري، وصلاحيات طالبين، وملف سليـم وآخر محجور، وفاتورة، ووصول دائم ومؤقت، ثم أعد تشغيل العوامل. لا تختبر استردادًا ماليًا حقيقيًا أثناء تجربة الاستعادة.

قبل ترحيل إنتاج: نسخة احتياطية مجرّبة، ومراجعة أثر إعادة فحص الملفات القديمة، وتهيئة ClamAV، والتحقق من المتغيرات والحسابات الخارجية. النشر والمتاجر خارج هذه المرحلة.

## فحوص المصدر
- npm run lint
- npm test
- داخل mobile: npm ci ثم npm run typecheck وnpm run lint وnpm test.
- npm run qa:store لاختبارات المعاملات على قاعدة اصطناعية حقيقية.
- scripts/qa-admin*.mjs لاختبارات الإدارة الحية بعد إعداد بيانات الاختبار والخادم.
- ملف verification/README_AR.md يبين ما نُفذ وما بقي معلقًا. نجاح تجميع JavaScript لمنصة هاتف لا يعادل نجاح تشغيلها على جهاز.
