# نتائج تدقيق منصة مراس العلم

## نطاق التدقيق

تمت مراجعة بنية مسارات Next.js API، عميل Expo المشترك، المصادقة والجلسات، التخزين على Railway Volume، الدفع عبر Tap، رفع الملفات والفيديو، الدعم، كونسول الإدارة، والـhealth endpoint. لا يشمل هذا الملف اختبارًا على Railway أو PostgreSQL أو Tap الإنتاجية أو أجهزة فعلية.

## نتائج مؤكدة وإصلاحات مطبقة

| المجال | الملاحظة | الإجراء |
|---|---|---|
| كلمات المرور | hash تالفة أو base64 غير صالحة كانت قد تسبب خطأ خادم بدل رفض الدخول | تغليف verifyPassword بمعالجة آمنة تعيد false |
| رفع الفيديو | نوع معلن مثل QuickTime/Matroska كان يمكن أن يمر دون بصمة حاوية مناسبة أو يرفض WebM/Matroska المتوافق | اشتراط magic bytes وتحديد توافق الحاويات وإبطال كاش الكتالوج بعد الرفع |
| الدفع | checkout بلا rate limit، وطلب Tap قد يعلق أو يترك order pending عند خطأ شبكة | إضافة rate limit، transaction لعناصر الطلب، مهلة 15 ثانية، وتحديث الحالة إلى failed عند فشل الاتصال/JSON |
| حذف الحساب الذاتي | لم يكن ذريًا، يترك مرفقات دعم محتملة، ويعدّل audit logs | جمع مرفقات الدعم والطلبات، transaction children-first، تنظيف الملفات بعد commit، منع حسابات الإدارة، وعدم إعادة كتابة audit logs |
| Push | التسجيل والإلغاء بلا rate limit | إضافة حد لكل مستخدم/IP |
| health | كان يعيد رسالة خطأ قاعدة البيانات التفصيلية | إرجاع حالة عامة فقط مع no-store وnosniff |
| الشعارات | endpoint العام كان يعرض كل شعار كـPNG حتى لو كان WebP/JPEG | اشتقاق Content-Type من امتداد مفتاح التخزين المسموح |

## نقاط يجب استمرار التحقق منها

1. يجب تنفيذ اختبارات عقدية لمسار checkout والرفع والفيديو وحذف الحساب الذاتي، دون استخدام بيانات إنتاجية.
2. يجب فحص الاستخدام المتزامن للكوبونات وحد الاستخدام في بيئة اختبار؛ لا تُحذف الطلبات أو الفواتير أو payment events عند أي حذف.
3. يجب تنفيذ اختبار قبول بعد النشر لرفع غلاف، شعار، فيديو، مرفق طلب، ومرفق دعم من الويب وExpo.
4. لا يمكن إثبات «استحالة الاختراق»؛ يمكن فقط تقليل سطح الهجوم، اختبار الضوابط، ومراقبة السجلات والتحديثات.
5. يجب تدوير الأسرار الإدارية وكلمات المرور التي سبق كشفها قبل أي نشر.

## تحسينات إضافية مؤكدة

| المجال | الإجراء |
|---|---|
| جلسة Expo | عند استجابة 401 يمسح التطبيق token المحفوظ، بينما يحتفظ به عند انقطاع الشبكة حتى لا يفرض تسجيل دخول جديدًا بلا داعٍ |
| MIME في Expo | أضيف اشتقاق النوع من امتداد الملف عند غياب mimeType لرفع مرفقات الطلب والدعم والشعارات والأغلفة والفيديو، مع بقاء فحص magic bytes خادميًا |
| الكتالوج | فُهرست المراجعات والوصول والوحدات والدروس داخل الذاكرة لتقليل filter المتكرر عند بناء كتالوج المواد |
| الاعتماديات | `npm audit --omit=dev --audit-level=high` أظهر صفر ثغرات high/critical في backend وmobile وقت الفحص |

## نتيجة الفحوص الحالية

نجح backend lint و`next build` و`node --test tests/*.test.mjs` بعدد 25/25 و`npx drizzle-kit check`. نجح Expo lint وtypecheck وExpo Doctor بنتيجة 21/21. بقيت تحذيرات غير مانعة معروفة فقط: أربعة تحذيرات صور `<img>` في الويب وتحذيران لنمط `Array<T>` في AppearanceSettings داخل Expo.

## الفحص النهائي قبل الإصدار

في آخر تشغيل كامل نجح `npm run lint` و`npm run build` و`node --test tests/*.test.mjs` بعدد 25/25 و`npx drizzle-kit check` في backend. ونجح `npm run typecheck` و`npm run lint` و`EXPO_PUBLIC_API_URL=https://api.example.invalid npx expo-doctor` بنتيجة 21/21 في Expo، كما نجح `git diff --check`. تحذيرات lint المتبقية غير مانعة ومحصورة في أربعة تحذيرات صور ويب وتحذيرين من نمط `Array<T>` في `AppearanceSettings.tsx`.

تم إجراء `npm audit --omit=dev --audit-level=high` في backend وmobile وأظهر صفرًا من ثغرات high/critical في لحظة الفحص. هذا الفحص لا يغني عن تحديث الاعتماديات دوريًا أو عن اختبار اختراق مستقل.

## ترقية مساعد مراس العلم

أضيف مصنف نوايا عربي خادمي يفهم التحية والتسجيل والدخول والاستعادة والملف والخصوصية والجامعات والتخصصات والمواد وطلبات المواد والملفات والسلة والمفضلة والدفع والكوبونات والتعلم والفيديو والإشعارات والدعم والمظهر والإدارة والمساعد. يطبع السؤال ويقبل المرادفات واللهجة والاختصارات والأخطاء الشائعة، ويعطي الأولوية لتطابق المادة قبل اسم الجامعة عند الحاجة.

أضيفت قوالب احتياطية تفصيلية تتضمن خلاصة وخطوات عملية وروابط داخلية واقتراحات متابعة بدل رسالة فشل عامة. طبقة النموذج أصبحت تطلب إجابة عربية منظمة بعناوين وفقرات وخطوات مرقمة، وتسمح بإجابة أطول حتى 4800 حرف، مع تمرير النية الخادمية وسياق مختصر. أُبقيت قيود عدم اختلاق السعر أو حالة الدفع، وعدم كشف الأسرار أو بيانات مستخدم آخر، وعدم طلب كلمة مرور أو بيانات بطاقة، وترشيح روابط الإجراءات قبل عرضها.

تم عزل ردود الدعم في سياق المستخدم بحيث لا تُقرأ إلا ردود تذاكره غير الداخلية، واستُبدلت استعلامات الإدارة التي كانت تجلب كل الصفوف باستعلامات count لتقليل الذاكرة والحمولة. قُصرت قائمة المواد المرسلة للنموذج مع إبقاء البحث الخادمي متاحًا، ووُضع السياق الخاص قبل قائمة الكتالوج حتى لا يُقص عند حد الحمولة. إذا تعطلت قراءة جلسة أو كتالوج غير حساس، يستخدم endpoint سياقًا عامًا ومحرك المعرفة المحلي بدل فشل المساعد كاملًا.

تم تحديث النموذج الافتراضي في ملف المثال إلى `gpt-5-mini`، مع استخدام `max_completion_tokens` لعائلة GPT-5، وبقاء المزود اختياريًا والمفتاح خادميًا فقط؛ عند عدم ضبط المزود تعمل المعرفة العربية المحلية. لا تُرسل مفاتيح أو سياقات خاصة إلى Expo أو المتصفح.

أضيف اختبار عقدي لجودة المساعد، وأصبح مجموع اختبارات backend الحالية 29/29 ناجحًا. كما نجحت فحوص البناء وDrizzle وExpo typecheck وlint وExpo Doctor 21/21 بعد هذه الترقية.

## حدود واقعية

لا يمكن ضمان أن يفهم المساعد كل سؤال في العالم أو أن تكون كل إجابة صحيحة بلا تحقق. الأسئلة العامة المتغيرة أو الطبية أو القانونية أو المالية تحتاج مصدرًا أو مختصًا، وبيانات الحساب والدفع لا تُحسم إلا من الخادم. لم يُنفذ استدعاء إنتاجي فعلي للمزود أو اختبار حذف/شراء على Railway في هذه البيئة؛ يلزم اختبار قبول بعد النشر بمفتاح مزود صحيح وبيانات غير مهمة.
